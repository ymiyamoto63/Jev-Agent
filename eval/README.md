# PoC-3: モデル別の実行結果からルーターを評価する（第1回: 20タスク）

実施日: 2026-10-03 / Claude Code 2.1.288 / Haiku 4.5・Sonnet 5.5（effort medium）・Opus 5.5（effort medium）/ 各組み合わせ1回ずつ / 実行費用の合計 **$5.55**

## 方法

- `fixture/`: 約200行の小さな shop パッケージ。既知のバグを6つ仕込んである（ページ番号のずれ、月末日の扱い、端数の丸め、並行処理の競合、割引の二重適用、SQL インジェクションと eval）。
- `tasks.py`: 20タスク（英語11、日本語9）。内訳は検索3、コマンド実行2、機械的な編集3、機能追加4、デバッグ5、レビュー2、設計1。プロンプトは、メインエージェントがサブエージェントに委譲する想定の文面にしてある。
- 採点: 隠しテスト（実行**後**にコピーするので、モデルからは見えない）、回答文の正規表現、ファイル内容の確認。`run_eval.py --check-graders` で、**修正前のプロジェクトでは20件すべて不合格、参照解答では20件すべて合格**になることを確認済み。
- 実行: `claude -p --model <m>` をタスクごとに新しいプロジェクトのコピーで実行する。**Agent ツールは無効**にしてあるので、1回の実行のコストと結果は1つのモデルだけのものになる。
- 分析（`analyze.py`）: 各タスクの正解ラベルを「合格したうち最も安いモデル」とし、ルーターごとの選択を記録済みの結果に当てはめて再生する。Claude を新たに呼ばないので、追加のコストはかからない。`+esc` は、失敗したら1段上のモデルで再実行する方式で、試したすべての実行の費用を合計する。

## わかったこと

1. **このタスク群は、モデルの差が出ないほど易しかった。** 20件中19件の正解ラベルが Haiku になった。小さなコードベースで仕様が明確な委譲タスクなら、検索・編集・デバッグ・レビュー・設計のどれでも Haiku で足りた。
2. **このタスク群では、事前に振り分ける余地がほとんどない。** oracle（$0.89）と all-haiku +esc（$0.91）の差は2%しかない。「まず安いモデルで実行し、失敗したら上位で再実行」が、判定器なしで oracle とほぼ同じ結果を出した。
3. **現在の判定ロジック（policy）は保守的すぎる。** mock で20件中16件を必要以上に上のモデルに振り分け、費用は oracle の2倍だった（それでも all-opus より45%安い）。原因は、レビュー・設計を Opus、デバッグ・機能追加を Sonnet とした基本モデル表。今回のデータではどちらも Haiku で足りていた。
4. **Opus を固定で使うのは割高。** 全タスク Opus は all-haiku の3.8倍の費用で、成功数は1件しか増えなかった。

## このデータで言えないこと（注意点）

- **難しいタスクがない**: 規模の大きいコードベース、仕様が曖昧なもの、手順の長いもの、複数ファイルにまたがる設計判断のように Haiku が失敗する領域を測れていない。モデルの差が出る境目を探すには、難しいタスク群が別に必要。
- **各組み合わせ1回だけ**: ばらつきは測っていない。合格・不合格の1件ずつの差には意味がない可能性がある。
- **mock は Jev ではない**: Jev 自体の判定精度は未評価。結果は `results/decisions-mock.json`。
- **成功判定が自動でできる前提**: `+esc` の数字は、失敗をテストで検出できることを前提にしている。レビューや設計、検索のように正解を機械で確かめにくいタスクでは、失敗に気づけず再実行も起きないので、この方式は成り立たない。
- **キャッシュの影響**: 各モデルの最初の実行はキャッシュの書き込みがあるぶん割高になる（例: 01 の Opus は $0.285、ほかの検索タスクは $0.08〜0.13）。実行順に左右される。

## 次の候補

1. **難しいタスク群（第2回）**: 実際の OSS リポジトリ（数千〜数万行）で、複数ファイルの変更、曖昧な要件、原因が深いバグを10〜20件。Haiku と Sonnet が失敗する領域を探す。
2. **方針の見直し**: 自動で検証できるタスクは「安いモデルから始め、失敗したら上位で再実行」を基本にし、Jev の判定は (a) 検証できないタスク（レビュー・設計・調査）のモデル選択と、(b) 最初から上位モデルに回すべき難しいタスクの見極め、に絞る。
3. **TypeSafe のキーが手に入ったら**: `JEV_BACKEND=http python3 eval/analyze.py` で、同じ記録に対して Jev の判定を再生する（Claude の追加費用はかからない）。
4. **試行回数を増やす**: 境目にあるタスクは各3回実行して、成功率で評価する。
